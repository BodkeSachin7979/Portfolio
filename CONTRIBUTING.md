Thank you for contributing! Please follow these guidelines to make collaboration smooth.

1. Code style
   - Follow the existing project's style (formatting, linting).
   - Run linters and formatters before committing.

2. Branches
   - Create feature branches from the default branch named: `feature/short-description` or `fix/short-description`.

3. Commit messages
   - Use concise, meaningful commit messages. Prefer Conventional Commits (e.g., `feat:`, `fix:`, `chore:`).

4. Pull requests
   - Open a PR against the default branch.
   - Describe the problem, the solution, and any migration or testing notes.
   - Link related issues (e.g., `Closes #123`).

5. Tests
   - Add or update tests for new behavior. Ensure CI passes before merging.

6. Local setup
   - See README for quickstart instructions. If missing, request maintainers add them.

7. Code of Conduct
   - Be respectful and professional. Report violations to the repository owner.

Thank you — maintainers will triage and respond to PRs as soon as possible.
